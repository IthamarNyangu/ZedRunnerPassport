# Roadmap and later dependencies

## Stage 2: community and provenance

### Clubs

Needs accounts, membership/role models, consent for contribution visibility, a defined eligible-activity source, time-bounded challenge rules, moderation/reporting and an auditable aggregate calculation. Rankings should be opt-in and should not reduce participation to speed.

### Organizer verification

Needs verified organizer identity, event ownership, result import or check-in workflow, immutable provenance/audit records, conflict and correction handling, and a deliberate transition from provisional to verified. A provisional stamp must never silently change status.

### Ten Provinces Challenge

Needs pilot-approved qualification and evidence rules, organizer verification support, a province geometry/art treatment, duplicate and boundary handling, and clear completion/version semantics if rules change. GPS border crossing alone must not count as a visit or finish.

## Stage 3: race-day support

### Water points

Needs an organizer-supplied course polyline, ordered hydration coordinates, along-course distance calculations, data validation, last-updated timestamps, offline caching and an explicit unavailable/stale state. Straight-line distance must not be presented as course distance.

### Live pacers (bus drivers)

Needs an organizer roster, target distance/time/pace, starting group, pacer consent, fresh runner and pacer positions, along-course matching, background location/battery strategy, field tests and a static pace-plan fallback. It must not promise a finish time.

## Deliberately outside this slice

General GPS tracking, payments, live navigation, AI photo matching, medical advice, nutrition personalization and organizer self-service are not prerequisites for validating the Stage 1 passport journey.
